# Physizen — документация для ИИ

Этот документ написан для нейросети. Он описывает плагин Physizen целиком: что это, как устроен, какие команды, теги и события есть, какие у них параметры и значения по умолчанию, и какие подводные камни есть в коде. Всё написано по исходникам репозитория (ветка main). Если в запросе пользователя есть то, чего нет в этом документе, значит, этого в плагине нет, и придумывать команды или теги нельзя.

Автор плагина: egor201. Пакет: `dev.egor201.physizen`.

---

## 0. Как использовать этот документ

Ты помогаешь пользователю в одной из двух ролей.

1. Писать Denizen-скрипты (`.dsc`), которые используют Physizen: команды `physworld`, `physbody`, `physforce`, `physconstraint`, `physfield`, `physhitbox`, теги `<physworld[...]>`, `<physbody[...]>`, события `on physbody ...`.
2. Дорабатывать Java-код самого плагина (раздел 16).

Правила для тебя:

- Используй только те команды, аргументы, теги и события, которые перечислены ниже. Других нет.
- Перед ответом сверься с разделом 14 «Подводные камни». Там перечислены места, где поведение отличается от того, чего можно ожидать.
- Если пользователь просит то, чего плагин не умеет (раздел 14.3), скажи об этом прямо и предложи обходной путь, а не выдумывай аргумент.
- Не давай несуществующих аргументов вроде `half_cone_angle:` или `max_velocity:`. Их нет в командах.

## 1. Что это

Physizen — аддон-плагин для Paper (API 1.21+), который добавляет в Denizen-скрипты настоящую твёрдотельную физику на движке Jolt (через `jolt-jni` 6.2.0). Тела, столкновения, трение, упругость, шарниры, пружины, силовые поля, рэйкасты.

Главные идеи:

- Физика считается в отдельном потоке `Physizen-Sim`, а не в основном потоке сервера.
- Физика живёт в «физических мирах» (physworld). Это абстракция плагина, не то же самое, что мир Minecraft. Физмир можно привязать к миру Minecraft, и тогда блоки становятся твёрдой землёй, а display-сущности следуют за телами.
- Тела (physbody) не имеют собственного вида. Чтобы тело было видно, к нему привязывают display-сущности (`block_display`, `item_display`, `text_display`) командой `physbody bind`.
- Игроки, мобы и предметы в физику не попадают сами. Для игрока есть готовая команда `physhitbox` (кинематическое тело, которое следует за игроком). Для мобов и предметов тело нужно создавать вручную.
- Ничего не сохраняется на диск. После рестарта сервера все миры и тела исчезают, скрипт должен создавать их заново.

## 2. Требования и установка

- Java 21.
- Paper 1.21+ (`api-version: 1.21`).
- Обязательно форк DenizenM, обычный Denizen не подходит. При старте плагин проверяет, что в Denizen есть класс `com.denizenscript.denizencore.scripts.queues.core.AsyncQueue` и поле `asyncSafe` у `AbstractCommand`. Если проверки не проходят, плагин пишет в лог `Physizen requires DenizenM fork!` и отключается.
- `plugin.yml`: `name: Physizen`, `main: dev.egor201.physizen.Physizen`, `depend: [Denizen]`.
- Команда Bukkit `/physizen` (право `physizen.admin`, по умолчанию op) выводит статус: число миров, откуда загружена нативная библиотека, по каждому миру число тел, число активных, на паузе или нет.
- Нативные библиотеки Jolt вшиты в jar (Linux x64, Linux x64 FMA, Linux ARM64, Windows x64, Windows x64 AVX2, Windows ARM64, macOS x64, macOS ARM64). При старте выбранная библиотека распаковывается в `plugins/Physizen/natives/`. Если положить свой файл `libjoltjni.so`, `joltjni.dll` или `libjoltjni.dylib` в `plugins/Physizen/natives/`, он будет загружен вместо вшитого.
- Файлы моделей для форм `hull`/`mesh` лежат в `plugins/Physizen/models/`.

Сборка: Gradle, `gradle shadowJar`, результат `build/libs/Physizen-<версия>.jar`. Paper API и Denizen подключены как `compileOnly`, Jolt как `implementation` (попадает в shadow jar). CI: `.github/workflows/build.yml` (JDK 21 Temurin).

## 3. Архитектура и потоки

```
Основной поток сервера                         Поток Physizen-Sim (daemon)
-----------------------                        ----------------------------
Denizen-команды  ──post(Runnable)──►  inbox ─►  drainInbox(): создать тело, сила, телепорт...
                                                 накопитель времени → шаги фикс. dt = 1/step_rate
                                                 applyFields() → Jolt update → publish(snapshot)
Теги/DisplayBinder  ◄──читают Snapshot (volatile)──
События (очередь)  ◄──offer(PhysEvent)──  contact/activation listeners
Terrain (блоки → static compound тела)
```

Ключевые факты:

- Команды ничего не считают сами. Каждая команда кладёт `Runnable` в очередь `inbox` нужного мира, поток симуляции выполняет её на следующей итерации (цикл спит по 1 мс, при отсутствии миров по 20 мс). Эффект команды виден не мгновенно, а в ближайшем шаге.
- Тело регистрируется в мире сразу (`world.body(name)` вернёт объект и `<physbody[..].exists>` будет `true`), но физически создаётся в Jolt позже, в потоке симуляции. Очередь команд строго последовательная (FIFO), поэтому `physforce`, `physbody teleport`, `physconstraint create` и `physbody bind`, вызванные сразу после `physbody create`, выполняются уже после создания тела. Исключение: если создание тела в Jolt не удалось (например, достигнут `max_bodies`), в лог пишется предупреждение, а тело удаляется.
- После каждого шага симуляции для каждого тела публикуется неизменяемый `Snapshot` (позиция, кватернион, скорости, AABB, активность, номер шага). Теги и `DisplayBinder` читают только снапшоты, поэтому теги безопасны из любых очередей.
- Спящие тела (Jolt deactivated) не публикуются повторно, их снапшот остаётся прежним.
- Каждый физмир имеет собственный `PhysicsSystem` Jolt и свои лимиты (`max_bodies` и остальные из конфига применяются на каждый мир отдельно).
- Шаг: `dt = 1 / step_rate`. Накопитель времени `accumulator += elapsed * time_scale`, за одну итерацию делается не больше `max_catchup_steps` шагов. Если симуляция отстаёт сильнее, лишнее время отбрасывается (замедление, а не взрыв из шагов).
- Раз в тик сервера (20 Гц) задача плагина на основном потоке: `displayBinder.tick()`, `terrainManager.tick()`, затем все накопленные события вызываются как Denizen-события.

## 4. Соглашения и форматы значений

Единицы:

- Длина: 1 блок = 1 метр. Время: секунды. Масса: кг. Угловая скорость: рад/с. Сила: Н. Импульс: кг·м/с.
- Гравитация по умолчанию `0,-9.81,0`.
- Вращение: кватернион `x,y,z,w`. Углы Эйлера (аргумент `euler:`): градусы, порядок компонентов `pitch,yaw,roll` (поворот вокруг X, Y, Z соответственно).

Значения аргументов:

| Тип | Что принимается |
|---|---|
| вектор | `LocationTag`, `VectorTag` или строка `x,y,z` (допустим префикс `l@` или `v@`). Нужно минимум три числа, лишние отбрасываются. |
| пара | строка `a,b` (минимум два числа, лишние отбрасываются). Используется в `damping:` и `limits:` |
| вращение | `QuaternionTag`, четыре числа `x,y,z,w` или три числа углов Эйлера в градусах `pitch,yaw,roll` |
| число | десятичное число; не число выдаёт ошибку `Invalid number` |
| булево | строго `true` или `false`, регистр не важен; иное выдаёт `Invalid boolean` |

Идентификаторы:

- id физмира: без `/` (тег `physworld@id` такие не принимает). Если id не указан, используется `default`.
- Имя тела уникально внутри мира. Префикс `__terrain_` зарезервирован под тайлы террейна.
- Рекомендация: только латиница, цифры, `_`, без пробелов.

Лимиты на число аргументов команды (токены через пробел, считая действие):

| Команда | Максимум |
|---|---|
| `physworld` | 12 |
| `physbody` | 24 |
| `physforce` | 8 |
| `physconstraint` | 20 |
| `physfield` | 16 |
| `physhitbox` | 16 |

Превышение лимита даёт ошибку Denizen о слишком большом числе аргументов. Лимиты подняты в патче (в оригинале было 8/12/6/14/12). Если у пользователя старая версия плагина, `physbody create` с большим числом параметров упрётся в лимит 12, тогда часть параметров нужно задавать через `physbody set`.

Формы можно передавать:

- Строкой-сокращением: `shape:box:1,2,1`, `shape:sphere:0.5`, `shape:capsule:0.3,1.8` (радиус, высота).
- Картой MapTag: `shape:<map[type=box;size=1,2,1]>`. Для сложных форм (`compound`, `hull`, `mesh`) только карта.

## 5. Физмир и мир Minecraft

Физмир (`physworld`) сам по себе не знает про блоки и сущности. Связь с миром Minecraft делается привязкой (`attach`):

- `physworld create id:arena attach:world` привязывает физмир `arena` к Bukkit-миру `world`.
- `physworld terrain id:arena attach:world` привязывает позже.
- Если Bukkit-мир с именем, равным id физмира, существует, привязка происходит автоматически (код делает `Bukkit.getWorld(id)` как запасной вариант).

Что даёт привязка:

1. Террейн. Блоки вокруг активных тел превращаются в статические коллайдеры (раздел 11).
2. `physbody bind` двигает display-сущности. Без привязки `DisplayBinder` ничего не обновляет, потому что не знает, в каком мире телепортировать сущности. Это самая частая причина «тело падает, а модель стоит на месте».
3. Теги `.location`, `.bounds_min`, `.bounds_max`, а также `context.point` в событии возвращают `LocationTag` с миром. Без привязки мир `null`.

Мир `default` (id по умолчанию) обычно не привязан ни к чему, если в Bukkit нет мира с таким именем.

## 6. Команды (справочник)

Во всех командах первый аргумент это действие. Ошибки валидации (`PhysException`) выводятся через `Debug.echoError`, скрипт при этом не падает, а команда просто ничего не делает.

### 6.1 `physworld`

Синтаксис: `physworld [create/remove/pause/resume/step/clear/gravity/time_scale/rate/collision/explosion/terrain] (id:<id>) ...`

Id мира задаётся как `id:<id>`, `world:<id>` или первым аргументом без префикса после действия. Если id нигде не указан, используется `default`.

| Действие | Параметры | Описание |
|---|---|---|
| `create` | `rate:<шагов/с>` (по умолчанию `tick_rate` из конфига), `gravity:<вектор>`, `attach:<имя Bukkit-мира>` | Создаёт мир. Если такой id уже есть, мир не пересоздаётся, но переданные `rate`, `gravity` и `attach` применяются к существующему. Если Bukkit-мир `attach` не найден, привязка молча пропускается. |
| `remove` | | Удаляет мир и все его тела. Привязанные display-сущности удаляются на ближайшем тике. |
| `pause` / `resume` | | Пауза/продолжение симуляции. Команды и `step` во время паузы продолжают работать. |
| `step` | `count:<n>` (по умолчанию 1) | Выполняет n шагов независимо от паузы. |
| `clear` | | Удаляет все тела мира, кроме внутренних (террейн). Ограничения (`physconstraint`) и поля (`physfield`) не удаляются. |
| `gravity` | `value:<вектор>` | Гравитация мира (блоки/с²). |
| `time_scale` | `value:<число>` | Множитель времени, не меньше 0. 0 останавливает симуляцию, 0.5 замедляет вдвое. |
| `rate` | `value:<число>` | Частота шага. Значение ограничивается диапазоном 1..480. |
| `collision` | `group_a:<0..15>`, `group_b:<0..15>`, `enable:<true/false>` (по умолчанию true) | Включает или выключает столкновения между двумя группами тел. |
| `explosion` | `center:<вектор>` (обязателен), `radius:<число>` (5), `impulse:<число>` (50), `upward:<число>` (0.2) | Один раз толкает все динамические тела в радиусе. |
| `terrain` | `attach:<имя Bukkit-мира>` | Привязывает физмир к Bukkit-миру (то же, что `attach` в create). |
| `refresh` | `center:<вектор>` и `radius:<число>` (по умолчанию 1) либо `min:<вектор>` и `max:<вектор>` | Помечает тайлы террейна в области как устаревшие и будит тела рядом, чтобы они пересчитали землю. Нужно после изменения блоков способами, которые не вызывают события Bukkit (`modifyblock` и подобное). Слишком большая область (больше 4096 тайлов) даёт ошибку. |

Замечания:

- Для `create` гравитация передаётся как `gravity:`, а для действия `gravity` значение идёт в `value:`. Для `rate` в create `rate:`, а для действия `rate` значение в `value:`.
- Взрыв: для каждого динамического тела в радиусе `falloff = 1 - dist/radius`, импульс `impulse * falloff` направлен от центра, плюс вертикальная добавка `upward * impulse * falloff`. Импульс применяется напрямую (изменение скорости равно импульс/масса), тяжёлые тела отлетают меньше. К блокам Minecraft это не относится.
- Групп ровно 16 (0..15). По умолчанию все группы сталкиваются со всеми и со статикой.

### 6.2 `physbody`

Синтаксис: `physbody [create/remove/teleport/move/set/bind/unbind/activate/deactivate] (world:<мир>) (name:<имя>) ...`

Мир задаётся `world:<id>` (по умолчанию `default`). Имя тела: `name:<имя>`, `body:<имя>` или первый аргумент без префикса после действия.

#### `physbody create`

Обязательны: `name`, `shape`. Параметры:

| Параметр | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `shape` | форма | обязателен | см. раздел 7 (позже можно сменить через `physbody set`) |
| `at` или `position` | вектор | `0,0,0` | позиция центра тела |
| `rotation` | вращение | единичный | начальная ориентация: кватернион, `x,y,z,w` или углы Эйлера в градусах |
| `euler` | вектор (градусы) | | альтернатива `rotation` (работает, если `rotation` не задан) |
| `type` | `static`/`kinematic`/`dynamic` | `dynamic` | тип движения |
| `mass` | число (кг) | 0 | при 0 масса считается Jolt из формы (по умолчанию плотность около 1000 кг/м³ на объём); при >0 масса задаётся вручную (только для dynamic) |
| `friction` | число | 0.5 | трение |
| `restitution` | число | 0.0 | упругость, 0 это без отскока, 1 это почти идеальный отскок |
| `linear_damping` | число | 0.05 | линейное затухание |
| `angular_damping` | число | 0.05 | угловое затухание |
| `gravity` | число | 1.0 | множитель гравитации для этого тела (не вектор!) |
| `group` | 0..15 | 0 | группа столкновений |
| `sensor` | булево | false | сенсор: не сталкивается физически, но фиксирует контакты |
| `continuous` | булево | false | непрерывное обнаружение (против туннелирования быстрых тел) |
| `allow_sleeping` | булево | true | разрешить засыпание |
| `notify` | булево | **true** | генерировать события collide/wake/sleep для этого тела |
| `remove_on_fall` | булево | true | удалять тело, если оно упало ниже `fall_out_y` |
| `tag` | строка | пусто | произвольная метка (читается тегом `.tag`) |
| `max_velocity` | число | 500 | максимальная линейная скорость, блоков/с |
| `max_angular_velocity` | число | 47.12 | максимальная угловая скорость, рад/с |
| `velocity` | вектор | 0,0,0 | начальная линейная скорость |
| `angular_velocity` | вектор | 0,0,0 | начальная угловая скорость |

Статические тела не активируются при создании и лежат в статическом слое. Динамические и кинематические создаются активными.

Ошибки: нет имени, нет формы, имя уже существует, группа вне 0..15, `mesh` (или `compound` с `mesh` внутри) на `dynamic`-теле.

#### Остальные действия

| Действие | Параметры | Описание |
|---|---|---|
| `remove` | | Удаляет тело и его привязанные сущности (если `remove_with_body` у привязки true). |
| `teleport` | `to:<вектор>` (обязателен), `rotation:` или `euler:` (необязательно) | Мгновенно переставляет тело и активирует его. Если вращение не задано, ориентация сохраняется. |
| `move` | `to:<вектор>` (обязателен), `rotation:` или `euler:`, `seconds:<число>` (0.05) | Плавно двигает кинематическое тело к цели за заданное время, так, что оно корректно толкает динамические тела. Минимальное время 1/240 с. Применять только к `type:kinematic`. |
| `set` | см. подраздел «Изменение тела на лету» ниже | Меняет свойства, форму, размер, тип и массу существующего тела без удаления и пересоздания. |
| `activate` / `deactivate` | | Разбудить или усыпить тело. |
| `bind` | `entities:<список сущностей>` (обязателен), `offset`, `scale`, `interpolation_duration` (алиас `interpolation`), `teleport_duration`, `interpolation_start` (алиас `interpolation_delay`), `remove_with_body` | Привязывает сущности к телу (раздел 12). |
| `unbind` | `entities:<список сущностей>` | Отвязывает указанные сущности (сами сущности не удаляются). |

#### Изменение тела на лету (`physbody set`)

Всё меняется прямо в Jolt, тело не пересоздаётся: сохраняются позиция, вращение, скорости, имя, ограничения (`physconstraint`) и привязанные display-сущности. Можно передавать несколько параметров в одной команде.

| Параметр | Что делает |
|---|---|
| `shape:<форма>` | Заменяет форму (любая из раздела 7). Масса пересчитывается по новой форме (если масса задана явно, она сохраняется). Нельзя задать `mesh` динамическому телу |
| `scale:<число>` | Умножает текущую форму на коэффициент (>0). Накопительный: `scale:2`, затем `scale:0.5` вернёт исходный размер. Размеры, радиусы, вершины hull/mesh и смещения детей compound масштабируются. Привязанные display-сущности масштабируются так же (`scale` и `offset`), отключается `scale_displays:false` |
| `display_scale:<x,y,z>` | Задаёт абсолютный масштаб всем привязанным display-сущностям (нужен после `shape:`, потому что размер формы и размер дисплея независимы) |
| `mass:<число>` | Задаёт массу в кг для динамического тела (инерция пересчитывается). `mass:0` возвращает автоматическую массу по объёму формы. Для не-динамических тел значение запоминается и применится при переключении на dynamic |
| `type:<static/kinematic/dynamic>` | Меняет тип движения (с учётом слоя столкновений). Тело, созданное как static, можно сделать dynamic. `mesh` нельзя сделать dynamic |
| `group:<0..15>` | Меняет группу столкновений |
| `sensor:<булево>` | Включает или выключает режим сенсора |
| `continuous:<булево>` | Включает или выключает непрерывное обнаружение столкновений |
| `allow_sleeping:<булево>` | Разрешает или запрещает засыпание (запрет будит тело) |
| `max_velocity:<число>`, `max_angular_velocity:<число>` | Лимиты скорости |
| `notify:<булево>`, `notify_persist:<булево>`, `remove_on_fall:<булево>`, `detect_static:<булево>` (только при создании: сенсор видит статику) | Флаги событий (`notify_persist` включает `contact persisted`) и удаления при падении |
| `friction`, `restitution` | Трение, упругость |
| `gravity:<число>` | Множитель гравитации тела |
| `damping:<линейное,угловое>`, `linear_damping`, `angular_damping` | Затухание |
| `tag:<текст>` | Метка тела |

Особенности:

- Внутренние тела террейна менять нельзя (ошибка).
- Форма, созданная заново (`shape:`), для `box`, `sphere`, `capsule`, `cylinder`, `cone` строится быстро, можно менять каждый тик (анимация роста, приседание). Для `hull`, `mesh`, `compound` с ними построение дороже, не меняй их каждый тик.
- При смене формы позиция тела (центр) не меняется. Ограничения остаются подключёнными, но их точки крепления заданы относительно старой формы.
- Для смены размера хитбокса игрока (`physhitbox`) используй `physbody set world:<мир> name:<имя> shape:<форма>` или `scale:`. Положение хитбокса относительно игрока (`offset`) при этом не меняется.
- Повторный `physbody bind` для той же сущности теперь заменяет прежнюю привязку (а не дублирует её).

Пример роста тела вместе с дисплеем:

```yaml
- physbody set world:arena name:crate1 scale:1.5
- physbody set world:arena name:crate1 type:kinematic mass:0 group:2 sensor:true
- physbody set world:arena name:ball shape:sphere:0.8 display_scale:1.6,1.6,1.6
```

Параметры `bind`:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `offset` | `0,0,0` | смещение сущности относительно центра тела в локальных осях тела (вращается вместе с телом) |
| `scale` | `1,1,1` | масштаб display-сущности. Перезаписывает масштаб сущности. Для `block_display` это размер блока в блоках, для текста или предмета коэффициент |
| `interpolation_duration` | 3 | длительность интерполяции трансформации (тики) |
| `teleport_duration` | 3 | длительность интерполяции телепорта (тики) |
| `interpolation_start` | 0 | задержка начала интерполяции (тики) |
| `remove_with_body` | true | удалять сущность, когда тело удалено |

### 6.3 `physforce`

Синтаксис: `physforce [force/impulse/torque/angular_impulse/velocity/angular_velocity/point_force/point_impulse] (world:<мир>) body:<имя> vector:<вектор> (point:<точка>)`

Тело: `body:`, `name:` или аргумент без префикса. Вектор: `vector:`, `v:` или `vec:`. Точка: `point:` или `at:` (мировые координаты).

| Действие | Что делает |
|---|---|
| `force` | сила (Н) в центр масс |
| `impulse` | импульс (кг·м/с) в центр масс, мгновенное изменение скорости на импульс/масса |
| `torque` | момент силы |
| `angular_impulse` | угловой импульс |
| `velocity` | **устанавливает** линейную скорость (и будит тело) |
| `angular_velocity` | **устанавливает** угловую скорость (и будит тело) |
| `point_force` | сила в точке (обязателен `point:`), создаёт и момент |
| `point_impulse` | импульс в точке (обязателен `point:`) |

Важно: `force`, `torque`, `point_force` в Jolt действуют только на ближайший шаг симуляции и затем сбрасываются. Одной командой раз в тик сервера (20 Гц) при частоте физики 60 Гц это даст сила только на один из трёх шагов. Для постоянного воздействия используй `physfield`, `impulse` в нужный момент или `velocity`. Если тело не найдено, выводится ошибка `Unknown body`.

### 6.4 `physconstraint`

Синтаксис: `physconstraint [create/remove] (world:<мир>) name:<имя> (type:<тип>) (body_a:<a>) (body_b:<b>) (point_a:<точка>) (point_b:<точка>) (axis:<вектор>) ...`

Имя задаётся только с префиксом: `name:` или `id:`.

Параметры `create`:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `type` | `point` | `fixed`, `point`, `hinge`, `slider`, `distance`, `cone` |
| `body_a`, `body_b` | | имена тел. Нужно хотя бы одно. Если одно не задано, соответствующий конец крепится к миру (неподвижная точка). Тела должны уже существовать |
| `point_a`, `point_b` | `0,0,0`, `point_b` = `point_a` | точки крепления в мировых координатах |
| `axis` | `0,1,0` | ось шарнира, ось ползуна, ось конуса |
| `normal` | `1,0,0` | нормальная ось для `hinge` (перпендикулярна `axis`) |
| `limits` | нет | `min,max` (два числа). Включает ограничения. Порядок значений не важен, меньшее станет минимумом |
| `degrees` | false | только для `hinge`: если true, `limits` заданы в градусах, а не в радианах |
| `cone_angle` | 45 | только для `cone`: угол полураствора конуса в градусах |
| `friction` | 0 | максимальное трение (момент для hinge, сила для slider) |
| `spring_freq` | 0 | частота пружины (только `distance`), включает пружину при >0 |
| `spring_damp` | 0.5 | демпфирование пружины |

Типы:

| Тип | Что это | Особенности |
|---|---|---|
| `fixed` | жёсткое соединение | точка определяется автоматически |
| `point` | шаровой шарнир | `point_a`/`point_b` |
| `hinge` | шарнир (дверь, колесо) | `limits` по умолчанию в **радианах** (или в градусах с `degrees:true`); минимум автоматически ограничивается диапазоном от -π до 0, максимум от 0 до π, как требует Jolt |
| `slider` | ползун | `limits` в метрах вдоль `axis`; точка автоопределяется |
| `distance` | верёвка или пружина | без `limits` дистанция фиксируется на текущем значении, с `limits:min,max,0` задаётся диапазон длины; `spring_freq` делает пружину |
| `cone` | конусный шарнир (плечо, хвост) | угол полураствора задаётся `cone_angle` (по умолчанию 45°) |

`physconstraint remove name:<имя>` удаляет ограничение. При удалении тела (командой, `physworld clear`, падением за `fall_out_y`) все ограничения, которые к нему подключены, удаляются автоматически.

### 6.5 `physfield`

Силовое поле действует на все динамические активные тела мира (не внутренние), у которых подходит группа. Поля применяются каждый шаг симуляции автоматически. Поле не привязано к телам и не хранится как тело.

Синтаксис: `physfield [create/remove] (world:<мир>) name:<имя> (type:<тип>) (center:<точка>) (radius:<r>) (strength:<s>) ...`

Имя только с префиксом `name:` или `id:`.

Параметры `create`:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `type` | `radial` | `radial`, `wind`, `vortex`, `drag`, `buoyancy`, `gravity` |
| `center` | `0,0,0` | центр поля |
| `direction` | `0,1,0` | направление (для `wind`, `gravity`, `vortex`) |
| `radius` | 10.0 | радиус; 0 значит «без ограничения» (для типов, где радиус используется) |
| `strength` | 1.0 | сила |
| `surface_y` | 0.0 | уровень поверхности (для `buoyancy`) |
| `density` | 1000.0 | плотность жидкости (для `buoyancy`) |
| `drag` | 0.5 | коэффициент сопротивления (см. формулы) |
| `mass_independent` | true | если true, сила умножается на массу, и `strength` выступает как ускорение (м/с²), одинаковое для любой массы; если false, `strength` это сила в ньютонах |
| `group` | -1 | `-1` значит все группы, иначе только тела этой группы |

Формулы по типам. `m` это масса (или 1, если `mass_independent:false`), `falloff = 1 - dist/radius` (при `radius=0` равен 1), `dist` это расстояние от тела до `center`:

| Тип | Радиус учитывается? | Сила |
|---|---|---|
| `radial` | да | к центру, величина `strength * falloff * m`. Отрицательный `strength` отталкивает |
| `gravity` | нет | `direction * strength * m` (направление не нормализуется). Действует на все тела мира (с учётом `group`) независимо от `center` и `radius` |
| `wind` | да | `(direction*strength - v) * drag * m * falloff`: тело разгоняется до скорости ветра `direction*strength` |
| `vortex` | да | вихрь вокруг вертикальной оси через `center`: касательная сила `strength * falloff * m` (при положительном `strength` по часовой стрелке при взгляде сверху), притяжение к оси `drag * falloff * m`, подъём `direction.y * strength * falloff * m * 0.25` (по умолчанию `direction.y = 1`, то есть есть лёгкий подъём) |
| `drag` | да | квадратичное сопротивление `-v * |v| * strength * falloff * m` |
| `buoyancy` | **нет** | см. ниже |

`buoyancy` не использует `center` и `radius`. Действует на все тела мира (с учётом `group`), чей AABB частично ниже `surface_y`. Доля погружения `s = clamp((surface_y - minY) / высота_AABB, 0..1)`, объём оценивается как `ширина*высота*глубина*0.6` AABB, подъёмная сила `density * |g| * объём * s * strength`, плюс вязкое торможение `-v * drag * s * m`. Это «бесконечный океан» на всю карту мира; чтобы ограничить, держи нужные тела в отдельной группе и указывай `group:`. Чтобы тело плавало, его масса должна быть заметно меньше `0.6 * density * объём`.

Поля действуют только на активные тела (`snapshot.active`), спящие поле не будит.

`physfield remove name:<имя>` удаляет поле.

### 6.6 `physhitbox`

Хитбокс игрока одной командой. Создаёт кинематическое тело Jolt, которое каждый тик сервера следует за игроком, и убирает его другой командой. Хитбокс толкает динамические тела, с которыми соприкасается, и передаёт им скорость движения игрока. Обратного влияния нет: тела не двигают самого игрока (это обычный Minecraft-игрок), для отдачи используй события и `physforce`/`velocity` на игроке средствами Denizen.

Синтаксис: `physhitbox [attach/detach] (player:<игрок>) (world:<физмир>) (name:<имя>) (shape:<форма>) (offset:<вектор>) (follow_rotation:<булево>) (group:<0..15>) (sensor:<булево>) (notify:<булево>) (friction:<число>) (restitution:<число>) (tag:<текст>)`

Имя тела только с префиксом `name:` или `body:`.

#### `physhitbox attach`

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `player` | привязанный к скрипту игрок | игрок, онлайн. Без `player:` и без привязанного игрока команда выдаёт ошибку |
| `world` | физмир, привязанный (`attach:`) к Bukkit-миру игрока | id физмира. Если подходящего физмира нет, ошибка с подсказкой |
| `name` | `hitbox_<ник игрока>` | имя тела в физмире (читается как `<physbody[<мир>/<имя>]>`) |
| `shape` | `capsule:0.3,1.8` | любая форма из раздела 7, включая `box`, `sphere`, `cylinder`, `hull`, `mesh`, `compound` |
| `offset` | `0, половина высоты формы, 0` | смещение центра формы от **ног** игрока. Если задан, заменяет значение по умолчанию целиком |
| `follow_rotation` | false | если true, тело поворачивается по yaw игрока, а `offset` вращается вместе с ним (нужно для не-симметричных форм, например box 0.8x1.8x0.4 или сенсора перед игроком) |
| `group` | 0 | группа столкновений |
| `sensor` | false | если true, хитбокс не толкает тела физически, а только фиксирует контакты (зона-триггер) |
| `notify` | true | генерировать события `collides`, `wakes`, `sleeps`, `falls out` |
| `friction` | 0.5 | трение |
| `restitution` | 0.0 | упругость |
| `tag` | пусто | метка тела |

Если хитбокс с таким же именем у этого игрока уже есть, он заменяется (удобно, чтобы сменить форму: повторить `attach` с другим `shape`). Если такое имя занято обычным телом, ошибка `already exists`.

Поведение:

- Тело всегда `kinematic`, не засыпает и не удаляется при падении ниже `fall_out_y` (игрок может быть в пустоте). Событие `falls out` приходит один раз.
- Каждый тик тело двигается к позиции игрока так, чтобы корректно толкать динамические тела. Если за тик игрок сместился больше чем на 6 блоков (например, телепорт), тело переставляется мгновенно.
- Форма не меняется сама при приседании, плавании, полёте на элитрах. Размер задаётся один раз при `attach`. Для приседания пересоздай хитбокс командой `attach` с другой формой.
- Режим наблюдателя (spectator) не отключает хитбокс. Если нужно, делай `detach`.
- Статические тела и террейн с кинематическим хитбоксом не сталкиваются (это свойство Jolt), игрок по-прежнему упирается в блоки обычной механикой Minecraft.

Автоматическое удаление: хитбокс удаляется, когда игрок выходит с сервера, меняет мир (в мир, не совпадающий с привязкой физмира), физмир удаляется или очищается (`physworld remove/clear`), тело удаляется командой `physbody remove`, плагин выключается.

#### `physhitbox detach`

`physhitbox detach (player:<игрок>) (name:<имя>) (world:<физмир>)`

Без `name` удаляет все хитбоксы игрока (по всем физмирам или только в указанном `world`). Игрок может быть не в сети. Если хитбоксов нет, команда ничего не делает.

Пример тега: `<physbody[arena/hitbox_Steve].player>` возвращает PlayerTag владельца хитбокса. Удобно в событии:

```yaml
physizen_hitbox_events:
    type: world
    events:
        on physbody collides:
        - define owner <context.body.player||null>
        - if <[owner]> != null && <context.speed> > 4:
          - hurt 1 <[owner]>
```


### 6.7 `physcharacter` (контроллер CharacterVirtual)

Синтаксис: `physcharacter [create/attach/detach/remove/move/jump/set/teleport] (world:<физмир>) (name:<имя>) (player:<игрок>) (at:<вектор>) (shape:<форма>) (velocity:<вектор>) (speed:<число>) (impulse:<вектор>) (mode:<driven/track>) (mass:<число>) (max_slope:<градусы>) (step_height:<число>) (walk_stairs:<булево>) (stick_to_floor:<булево>) (push:<булево>) (inner_body:<булево>) (gravity:<число>) (group:<0..15>) (notify:<булево>) (tag:<текст>)`

CharacterVirtual это капсула (или любая выпуклая форма), которая скользит по террейну и телам, поднимается по ступеням, прилипает к полу и склонам, едет на движущихся платформах и толкает динамические тела. Позиция персонажа это точка между ногами. Форма по умолчанию `capsule:0.3,1.8` (радиус, полная высота). Меш использовать нельзя.

- `create` создаёт управляемого (`driven`) персонажа: `at:<вектор>` позиция, остальное по умолчанию (масса 70, склон 50°, ступень 0.6, `walk_stairs`, `stick_to_floor`, `push` включены).
- `move velocity:<вектор>` задаёт желаемую скорость ходьбы (горизонтальную), её нужно повторять каждый тик, нулевой вектор останавливает. Вертикаль считают гравитация и прыжок.
- `jump speed:<число>` прыжок с начальной вертикальной скоростью (срабатывает только с земли).
- `set` принимает `velocity:` (заменить скорость один раз), `impulse:` (разовый импульс), `gravity:` (множитель гравитации).
- `teleport at:<вектор> (rotation:...)` мгновенное перемещение со сбросом скорости.
- `attach` создаёт отслеживающий (`track`) персонаж, который повторяет положение игрока (`player:` или связанный игрок, мир берётся из привязки мира игрока). Игрока по-прежнему двигает Minecraft, персонаж толкает тела, на которые игрок наступает, показывает состояние земли под ногами и вызывает сенсорные зоны. Имя по умолчанию `controller_<ник>`. Лестницы и прилипание в этом режиме отключены.
- `detach` удаляет отслеживающие персонажи игрока (всех, или одного по `name:`). Они также удаляются при выходе игрока, смене мира и удалении мира.
- `remove name:<имя>` удаляет любого персонажа.

При `inner_body:true` (по умолчанию) у персонажа есть кинематическое внутреннее тело с тем же именем: оно видно в `physbody[мир/имя]`, ловится рэйкастом, срабатывает в сенсорных зонах и в контактных событиях. Это тело нельзя двигать командами `physbody` (телепорт и скорость перенаправляются персонажу, остальное игнорируется), оно не сохраняется в префабы и его нельзя использовать в `physconstraint`.

ObjectTag `PhysCharacterTag` (`physcharacter[мир/имя]`): `name`, `exists`, `location` (ноги), `velocity`, `ground_state` (`ON_GROUND`, `ON_STEEP_GROUND`, `NOT_SUPPORTED`, `IN_AIR`), `on_ground`, `is_supported`, `ground_normal`, `ground_velocity`, `ground_body`, `mode`, `body`, `player`, `world`, `speed`, `horizontal_speed`, `is_falling`, `is_rising`, `is_tracking`, `mass`, `shape`, `sensors` (сенсорные зоны, в которых стоит персонаж).

```yaml
- physcharacter create world:arena name:guard at:<location[0,65,0]>
- physcharacter move world:arena name:guard velocity:0,0,3
- physcharacter jump world:arena name:guard speed:7
- physcharacter attach
- if <physcharacter[arena/guard].on_ground>:
    - narrate "На земле"
```

## 7. Формы (shape)

Допустимые `type`:

| type | Ключи карты | Сокращение | Заметки |
|---|---|---|---|
| `box` или `cube` | `size` (x,y,z полные размеры, по умолчанию 1,1,1) | `box:x,y,z` или `box:a` (куб) | |
| `sphere` | `radius` (0.5) | `sphere:r` | |
| `capsule` | `radius` (0.25), `height` (1.0, **полная высота с шапками**) | `capsule:r,h` | |
| `cylinder` | `radius` (0.5), `height` (1.0) | `cylinder:r,h` | ось по Y |
| `cone` | `radius` (0.5), `height` (1.0), `segments` (16) | `cone:r,h` | выпуклая оболочка, вершина вверху, основание внизу |
| `hull` или `convex_hull` | `file` или `points` | нет | выпуклая оболочка; допустима для динамических тел; минимум 4 точки |
| `mesh` | `file` или `points` + `triangles` | нет | невыпуклая сетка; **только static или kinematic** |
| `compound` | `children` (список карт) | нет | составная форма |

Общий ключ `scale` (число, по умолчанию 1) умножает размеры формы (и смещения детей в compound).

`compound`: каждый элемент `children` это карта формы плюс необязательные `offset` (вектор), `rotation` (кватернион) или `euler` (градусы). Пример:

```
- define shape <map[type=compound;children=<list[<map[type=box;size=1,0.2,1;offset=0,0,0]>|<map[type=box;size=0.2,1,0.2;offset=0,0.6,0]>]>]>
- physbody create world:arena name:t shape:<[shape]> at:<[loc]> mass:10
```

Файловые модели: `file:model.obj` читается из `plugins/Physizen/models/`. Путь не должен содержать `..` и не может начинаться с `/` или `\`. Парсер OBJ читает строки `v` и `f`, многоугольные грани разбивает веером на треугольники, понимает отрицательные индексы, игнорирует `vt` и `vn`. Для `hull` используются только вершины, для `mesh` вершины и индексы. Для `points` каждый элемент это вектор, `triangles` это список индексов вершин (по три на треугольник).

Для `box`, `sphere`, `capsule`, `cylinder` есть минимальные размеры (около 0.005, у цилиндра 0.01).

## 8. Теги

Глобальные теги-входы: `<physworld[<id>]>` и `<physbody[<мир>/<имя>]>`. Префиксы `physworld@` и `physbody@` необязательны. Формат идентификации: `physworld@<id>`, `physbody@<мир>/<имя>`. Теги читают снапшоты и безопасны из async-очередей DenizenM. Значения обновляются раз за шаг симуляции.

`physworld[id]` возвращает `null`, если мира нет. `physbody[...]` не проверяет существование, используй `.exists`.

## 9. События

Объявляются в мир-скрипте `type: world`:

| Событие | Когда |
|---|---|
| `on physbody collides:` | началось касание двух тел (или тела и террейна) |
| `on physbody sleeps:` | тело заснуло |
| `on physbody wakes:` | тело проснулось |
| `on physbody falls out:` | тело опустилось ниже `fall_out_y` |

Фильтров и switch-ей у событий нет, фильтруй условиями внутри обработчика.

Контекст:

| Контекст | collides | sleeps/wakes | falls out |
|---|---|---|---|
| `<context.body>` | PhysBodyTag | PhysBodyTag | PhysBodyTag |
| `<context.world>` | PhysWorldTag | PhysWorldTag | PhysWorldTag |
| `<context.other>` | PhysBodyTag второго тела или элемент `terrain` | нет | нет |
| `<context.point>` | приблизительная точка контакта (см. ниже) | нет | нет |
| `<context.normal>` | приблизительная нормаль контакта (см. ниже) | нет | нет |
| `<context.speed>` | относительная линейная скорость контакта | нет | нет |

Нормаль и глубина берутся из реального манифеста контакта Jolt, точка остаётся приблизительной (Jolt-JNI не отдаёт точки манифеста):

- `normal` для `context.body` направлена от другого тела (или террейна) к `context.body`. При падении на землю это `0,1,0`. Для `contact removed` манифеста уже нет, нормаль считается по снапшотам.
- `depth` это глубина проникновения из манифеста (0 для `contact removed`).
- `point` это центр пересечения AABB двух тел; для террейна точка на границе AABB тела со стороны контакта.

### Жизненный цикл контакта и сенсорные зоны

| Событие | Когда срабатывает |
|---|---|
| `physbody collides` | появился контакт (Jolt `added`), относительная скорость не ниже `contact_min_speed`, нужно `notify:true` |
| `physbody contact persisted` | пока тела соприкасаются, раз в `contact_persist_interval_steps` шагов (по умолчанию 6). Только для тел с `notify_persist:true`. Фильтра по скорости нет |
| `physbody contact removed` | исчезла последняя точка контакта пары. Приходит для каждой отслеживаемой пары (`notify:true`), в том числе для медленных контактов, которые не дали `collides` |
| `physsensor enter` | тело начало пересекать сенсорную зону (`sensor:true`) |
| `physsensor exit` | пересечение закончилось; также при удалении тела или зоны |
| `physsensor stay` | пока тело внутри, раз в `sensor_stay_interval_steps` шагов. По умолчанию выключено (0) |

Контекст `physsensor *`: `<context.sensor>` (зона), `<context.body>` (вошедшее тело), `<context.player>` и `<context.is_player>` (если тело принадлежит хитбоксу или контроллеру игрока), `<context.point>`, `<context.speed>`, `<context.world>`. События зоны требуют `notify:true` у самой зоны (по умолчанию true). Контакты с террейном в зонах не учитываются.

Кто обнаруживается сенсором: динамические тела, кинематические тела (хитбоксы игроков, внутренние тела персонажей). Статическая зона не видит статические тела. Кинематической зоне, которая должна видеть статику и другие кинематические тела, нужно `detect_static:true` при создании. Сенсоры не видят друг друга. Статическая зона учитывает `group` так же, как обычное тело.

Теги: `<PhysBodyTag.is_sensor>`, `<PhysBodyTag.sensor_contents>` (список тел внутри зоны), `<PhysBodyTag.in_sensors>` (зоны, в которых находится тело), `<PhysBodyTag.is_character>`.

Правила срабатывания:

- `collides` срабатывает только для тел с `notify:true` (в команде по умолчанию true) и только если относительная скорость контакта не ниже `contact_min_speed` (0.5 м/с по умолчанию). Медленные касания и лежание тел друг на друге событий не дают.
- Если у обоих тел `notify:true`, событие вызывается дважды (по разу для каждого тела, где `context.body` это «своё» тело).
- Контакт с террейном даёт событие с `other = terrain`.
- `sleeps`/`wakes` только для тел с `notify:true`.
- `falls out` вызывается для всех не-статических тел, упавших ниже `fall_out_y` (проверка по абсолютной координате Y, независимо от высоты мира Minecraft). Событие приходит один раз за падение. Если тело вернули выше `fall_out_y` (и `remove_on_fall:false`), оно может сработать снова при следующем падении.
- События ставятся в очередь потока симуляции и вызываются на основном потоке раз в тик. Лимит очереди `contact_event_queue_limit` (4096), сверх лимита события отбрасываются.

Пример проверки «ударился о землю»:

```yaml
physizen_events:
    type: world
    events:
        on physbody collides:
        - if <context.other> == terrain && <context.speed> > 6:
          - announce "Удар: <context.body.name> со скоростью <context.speed.round_to[1]>"
```

## 10. Группы столкновений

- Номера 0..15.
- Статические тела (и террейн) лежат в отдельном статическом слое и сталкиваются со всеми группами всегда (это не отключается).
- Между динамическими и кинематическими телами столкновение по умолчанию включено для всех пар групп. `physworld collision group_a:1 group_b:2 enable:false` отключает пару.
- `group` у `physfield` фильтрует, на какие тела действует поле (`-1` это все).

Типичный сценарий: группа 1 для игровых снарядов, группа 2 для декораций, отключить пару 1–1, чтобы снаряды не сталкивались друг с другом.

## 11. Террейн (блоки Minecraft)

Включается автоматически для привязанных миров. Реализован классом `TerrainManager`.

- Мир делится на тайлы 16×16×16 блоков.
- Для каждого активного нестатического тела вычисляются тайлы вокруг его AABB (по X/Z с запасом в 1 тайл, по Y с запасом). Для этих тайлов создаётся статическое внутреннее тело `__terrain_<tx>_<ty>_<tz>` (составная форма из боксов) с трением 0.6 и упругостью 0.05.
- Полные кубы объединяются жадным алгоритмом в крупные боксы; неполные блоки (плиты, лестницы, заборы) становятся наборами боксов по их коллизионной форме Bukkit (`BlockData.getCollisionShape`). Воздух не создаёт коллизии. Кэш форм: до 4096 типов блоков.
- Строятся только тайлы в загруженных чанках; не более 16 новых снапшотов чанков за тик.
- Тайл пересобирается при событиях Bukkit: `BlockBreakEvent`, `BlockPlaceEvent`, `BlockExplodeEvent`, `EntityExplodeEvent`, `EntityChangeBlockEvent`, поршни (`BlockPistonExtendEvent`, `BlockPistonRetractEvent`), `BlockBurnEvent`, `LeavesDecayEvent`, `BlockFadeEvent`, `BlockFormEvent`. Все нестатические тела около изменённого места будятся, чтобы упасть или скатиться.
- Неиспользуемые тайлы удаляются примерно через 400 тиков, если в них нет тел (проверка раз в 200 тиков).
- Внутренние тела скрыты от `.bodies`, `.body_count`, `bodies_in_*`, `ray_cast` (ключ `body` не выставляется) и событий (`other = terrain`).

Ограничение: изменения блоков, которые не вызывают перечисленные Bukkit-события (например `modifyblock` из Denizen), террейн сам не увидит. После таких изменений вызывай `physworld refresh center:<точка> radius:<n>`. Спящие тела землю не требуют: тайл создаётся, когда рядом есть активное тело.

## 12. DisplayBinder (привязка сущностей к телам)

Класс `DisplayBinder` раз в тик сервера синхронизирует привязанные сущности со снапшотом тела, если номер шага изменился с прошлого раза.

Для `Display`-сущностей (`block_display`, `item_display`, `text_display`):

- Итоговый поворот = поворот тела × (внутренний `rotationOffset`, в текущей команде всегда единичный). Знак кватерниона выравнивается для плавной интерполяции.
- Трансформация (`translation`, `rotation`, `scale`) обновляется, только если кватернион изменился заметно (порог 0.0005 по компоненте).
- Для `BlockDisplay` translation вычисляется так, чтобы центр блока совпал с позицией тела (`offset` поворачивается телом, из него вычитается повёрнутая половина `scale`). Поэтому для `block_display` задавай `scale:` равным размеру формы в блоках. Для box `1,2,1` это `scale:1,2,1`. Для `item_display`/`text_display` translation равен только повёрнутому `offset`, начало координат в центре.
- Сама сущность каждый тик телепортируется в позицию тела с `teleport_duration` для плавности.
- Параметры `interpolation_duration` (3), `teleport_duration` (3), `interpolation_start` (0) в тиках.

Для не-Display сущностей: просто телепорт в `позиция тела + повёрнутый offset`, без вращения.

Очистка: если тело удалено (командой, `physworld clear/remove`, падением за `fall_out_y`), привязанные сущности удаляются на ближайшем тике (если `remove_with_body:true`).

## 14. Подводные камни

### 14.1 Особенности и оставшиеся ограничения

Версия документа описывает патченную версию плагина (см. `CHANGES.md` в репозитории). Что осталось:

1. **`ray_cast.normal`** это обратное направление луча, а не нормаль поверхности. Не используй для отражений.
2. **`<context.normal>` и `<context.point>`** в событии `collides` приближённые (раздел 9).
3. **`gravity:`** у `physworld` это вектор (блоки/с²), а у `physbody` это множитель (число). Не путай.
4. **`notify` по умолчанию `true`** в команде (в классе `BodyDef` `false`). Для тысяч тел без обработчиков ставь `notify:false`.
5. `physworld clear` не удаляет поля (`physfield`). Ограничения, привязанные к удалённым телам, удаляются автоматически.
6. Тела и миры не сохраняются при перезапуске. Пересоздавай их в `on server start` и т. п.
7. Силы `force`/`torque`/`point_force` живут один шаг симуляции (раздел 6.3).
8. `buoyancy` и `gravity` поля игнорируют радиус и действуют на весь мир.
9. Тела имеют ограничения скорости: по умолчанию 500 блоков/с линейно и 47.12 рад/с угловой (меняется `max_velocity` и `max_angular_velocity` при create). Для быстрых тел включай `continuous:true`.
10. Старые версии плагина (до патча) имели ошибки: `rotation:` в `teleport`/`move` не работал, `damping` и `limits` требовали три числа, угол `cone` был фиксирован, а лимиты аргументов были ниже. Если у пользователя поведение не совпадает с документом, спроси, какая у него версия.

### 14.2 Полезные практики

- Всегда привязывай физмир к миру Minecraft (`attach:`), если нужны блоки или display.
- Для плавной картинки держи `rate:60` и интерполяцию 3 тика.
- Для статичных коллайдеров (платформы, стены) используй `type:static` с формой `box` или `mesh`. Они бесплатны, пока никто не двигается.
- Для заготовок на `item_display` и `text_display` используй `scale:` и `offset:` для выравнивания модели относительно центра формы.
- Профилируй: `<physworld[id].step_millis>` и `/physizen`.
- Чтобы игрок мог толкать тела, используй `physhitbox attach` (раздел 6.6), вручную двигать тело не нужно.

### 14.3 Чего в плагине нет

- Автоматических тел для мобов и предметов (для игроков есть `physhitbox`). Для мобов и предметов тела создаются вручную.
- Обратного воздействия физики на игрока: хитбокс толкает тела, но тела не двигают самого игрока.
- Автоматической смены формы хитбокса при приседании или плавании.
- Сохранения состояния на диск.
- Событий о разрушении ограничений.
- Точных нормалей и точек контакта (есть только приближения).

## 15. Рецепты

### 15.1 Ящик с блоком-дисплеем

```yaml
physizen_crate:
    type: task
    script:
    - physworld create id:arena attach:<player.location.world.name> rate:60
    - define loc <player.location.above[5]>
    - spawn block_display[material=oak_planks] <[loc]> save:disp
    - physbody create world:arena name:crate1 shape:box:1,1,1 at:<[loc]> mass:20 restitution:0.2 friction:0.6 notify:false
    - physbody bind world:arena name:crate1 entities:<entry[disp].spawned_entity> scale:1,1,1
```

### 15.2 Мяч с отскоком и реакцией на удар

```yaml
physizen_ball:
    type: task
    script:
    - physworld create id:arena attach:<player.location.world.name>
    - define loc <player.eye_location.forward[1.5]>
    - spawn item_display[item=white_wool] <[loc]> save:disp
    - physbody create world:arena name:ball shape:sphere:0.4 at:<[loc]> mass:1 restitution:0.8 velocity:<player.location.direction.vector.mul[8]>
    - physbody bind world:arena name:ball entities:<entry[disp].spawned_entity> scale:0.8,0.8,0.8

physizen_ball_events:
    type: world
    events:
        on physbody collides:
        - if <context.speed> > 5:
          - playsound <context.point> sound:block_wool_hit volume:1
```

### 15.3 Дверь на шарнире

```yaml
physizen_door:
    type: task
    script:
    - physworld create id:arena attach:<player.location.world.name>
    - physbody create world:arena name:frame shape:box:0.2,2,0.2 at:10,64,10 type:static
    - physbody create world:arena name:door shape:box:1,2,0.1 at:10.6,64,10 mass:15
    - physconstraint create world:arena name:door_hinge type:hinge body_a:frame body_b:door point_a:10.1,64,10 axis:0,1,0 limits:-1.5,1.5 friction:2
```

### 15.4 Взрыв

```yaml
- physworld explosion id:arena center:<player.location> radius:8 impulse:120 upward:0.3
```

### 15.5 Ветер и вихрь

```yaml
- physfield create world:arena name:wind1 type:wind center:<player.location> radius:12 direction:1,0,0 strength:8 drag:0.8
- physfield create world:arena name:tornado type:vortex center:<player.location> radius:15 strength:6 drag:2
- physfield remove world:arena name:wind1
```

### 15.6 Вода (плавучесть)

```yaml
- physfield create world:arena name:sea type:buoyancy surface_y:62 density:1000 drag:1.5 strength:1 group:3
- physbody create world:arena name:boat shape:box:2,0.5,1 at:10,63,10 mass:200 group:3
```

Для плавучести масса должна быть ниже `0.6 * density * объём`; здесь `0.6 * 1000 * 1 = 600`.

### 15.7 Луч из глаз игрока

```yaml
physizen_ray:
    type: task
    script:
    - define hit <physworld[arena].ray_cast[<player.eye_location>|<player.location.direction.vector>|50]>
    - if <[hit].get[hit]> && <[hit].contains[body]>:
      - physforce impulse world:arena body:<[hit].get[body].name> vector:0,6,0
```

### 15.8 Верёвка (distance)

```yaml
- physbody create world:arena name:anchor shape:sphere:0.1 at:10,70,10 type:static
- physbody create world:arena name:weight shape:sphere:0.4 at:10,66,10 mass:5
- physconstraint create world:arena name:rope type:distance body_a:anchor body_b:weight point_a:10,70,10 point_b:10,66,10 limits:0,4
```

### 15.9 Хитбокс игрока

```yaml
physizen_hitbox_on:
    type: task
    script:
    - physworld create id:arena attach:<player.location.world.name>
    - physhitbox attach world:arena shape:capsule:0.35,1.8 friction:0.4

physizen_hitbox_off:
    type: task
    script:
    - physhitbox detach
```

Хитбокс-сенсор перед игроком (зона удара), поворачивающийся вместе с игроком:

```yaml
- physhitbox attach name:strike shape:box:1.2,1,1.2 offset:0,1,1.2 follow_rotation:true sensor:true
```

### 15.10 Платформа, которую двигают

```yaml
- physbody create world:arena name:lift shape:box:3,0.3,3 at:20,64,20 type:kinematic
- physbody move world:arena name:lift to:20,70,20 seconds:3
```

Для движения по кругу или маятником вызывай `move` каждый тик.

## 16. Для разработчиков: структура кода

Один репозиторий, четыре Gradle-модуля. Зависимости идут только вниз: `plugin` → `denizen` → `bukkit` → `core`.

```
physizen-core/       чистая физика на Jolt, без Bukkit и Denizen
  core/PhysException.java
  core/model/        данные: BodyDef, ShapeSpec, ConstraintDef, FieldDef, CharacterDef, Snapshot, MotionKind, QueryFilter
  core/engine/       EngineConfig, NativeLoader
  core/shape/        ShapeBuilder (ShapeSpec → форма Jolt), ObjParser
  core/constraint/   ConstraintFactory, ConstraintMotors
  core/validate/     Guard (проверка входных данных)
  core/io/           PhysBinary (формат .phys)
  core/world/        PhysEngine (синглтон, поток симуляции), PhysWorld (фасад мира), StepLoop (шаг и публикация снапшотов), ConstraintService, WorldSpatial (взрывы и выборки), PhysBody, PhysCharacter, CharacterState,
                     ContactTracker (контакты added/persisted/removed + сенсорные зоны), ContactGeometry, FieldSolver,
                     BodyFactory, WorldLayers, WorldQueries, EventQueue, PhysEvent, QueryHit, RayHit
physizen-bukkit/     слой Bukkit
  bukkit/PhysizenServices, WorldLinks    общий доступ к сервисам и привязкам миров (вместо синглтона плагина)
  bukkit/display/    DisplayBinder, BindingHooks
  bukkit/terrain/    TerrainManager
  bukkit/hitbox/     HitboxManager
  bukkit/character/  PlayerControllerManager (отслеживающие персонажи игроков)
  bukkit/status/     StatusBarManager
physizen-denizen/    слой Denizen
  denizen/DenizenBridge, DenizenServices
  denizen/args/      Args (вектор, число, булево, кватернион, сущности), ShapeParser, ShapeCodec
  denizen/command/   Phys{World,Body,Force,Constraint,Field,Hitbox,Character}Command
  denizen/tag/       PhysWorldTag, PhysBodyTag, PhysCharacterTag
  denizen/event/     PhysScriptEvents (collides, contact persisted/removed, physsensor enter/exit/stay, sleeps, wakes, falls out)
  denizen/save/      SaveManager (тела, префабы, привязки), ConstraintCodec (ограничения), PrefabFiles (файлы .phys/.json, blob), PersistenceManager
physizen-plugin/     точка входа и ресурсы: Physizen.java, PluginSettings, AdminCommand, plugin.yml, config.yml; собирает shaded jar
```

Правила при доработке:

- Никогда не трогай Jolt-объекты из основного потока. Контактные колбэки Jolt приходят из рабочих потоков, поэтому всё в `ContactTracker` и `EventQueue` потокобезопасно. Всё через `world.post(...)`, читать можно только `Snapshot`.
- Новая команда: класс, наследующий `AbstractCommand`, с Denizen meta-комментарием `// <--[command] @Name @Syntax @Required @Maximum @Short @Group Physizen -->` и регистрацией в `DenizenBridge.registerAll()` через `DenizenCore.commandRegistry.registerCommand(...)`.
- Новый тег: `tagProcessor.registerTag(...)` внутри `register()` у `PhysWorldTag`/`PhysBodyTag`/`PhysCharacterTag` с meta-блоком `// <--[tag] @attribute ... @returns ... @description ... @group Physizen -->`.
- Новое событие: наследник `ScriptEvent`, `registerCouldMatcher("...")`, регистрация в `PhysScriptEvents.registerAll()` и ветка в `PhysScriptEvents.fire`; тип события добавляется в `PhysEvent.Kind`, источник события это `ContactTracker`.
- Автор в коде: egor201. Комментарии в коде проекта не используются, кроме Denizen meta-блоков.
